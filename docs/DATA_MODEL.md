# 📐 KidQuest Authoritative Data Model & Security Architecture (Phase 3)

**Version:** 1.0.0  
**Status:** Approved for Implementation  
**Audience:** Mobile Engineers (React Native / Expo), Backend Engineers (Cloud Functions), Security Reviewers  
**Philosophy:** Ponytail (Minimalist, zero bloat, high security) + COPPA / DPDP 2023 Child Privacy Compliance  

---

## 1. Architectural Principles & COPPA/DPDP Compliance

1. **Server-Authoritative Gamification (Anti-Cheat):**
   - Client applications (Kids/Parents) **never** directly increment XP, alter streaks, unlock badges, or approve their own reward redemptions.
   - All XP grants and deductions flow through Cloud Functions via atomic Firestore Transactions and are recorded in an immutable `XpLedger`.
2. **Zero-PII Storage for Minors (Under-13):**
   - Children do not register with email addresses, phone numbers, or passwords.
   - Children accounts are child-profiles created by and linked to a verified Parent (`parentId`).
   - Authentication for children uses either:
     a) Parent session delegation (instant switch via local 4-digit PIN), or
     b) Firebase Custom Auth Token generated by `generateKidCustomToken` Cloud Function.
3. **Least Privilege Role-Based Access Control (RBAC):**
   - Firebase Auth Custom Claims (`request.auth.token.role`) determine the base role (`parent`, `kid`, `teacher`, `admin`).
   - Sub-document lookups verify specific family linkages (`linkedParentId == request.auth.uid` or `assignedToUid in parent.linkedKids`).
4. **Child Media Privacy (Anti-Leak):**
   - Photos uploaded as task proof (`task-photos/{taskId}/{fileName}`) are **strictly private**. Only the assigned child, the assigning parent, and the student's verified class teacher can read/download the image.
   - Global `allow read: if isSignedIn();` is completely forbidden.

## 2. Firebase Auth Custom Claims Schema

Har user ke Firebase Auth token me ek secure `role` custom claim store hota hai, jo Cloud Function ke zariye set hota hai (client directly set nahi kar sakta):

```typescript
interface CustomAuthClaims {
  role: 'parent' | 'kid' | 'teacher' | 'admin';
  parentId?: string;      // Only present on 'kid' tokens (links to managing parent)
  schoolId?: string;      // Only present on 'teacher' tokens
  consentGiven?: boolean; // Verified parental consent flag
}
```

### Security Rules Helper Usage:
```javascript
function hasRole(role) {
  return request.auth != null && request.auth.token.role == role;
}
function isParent()  { return hasRole('parent'); }
function isKid()     { return hasRole('kid'); }
function isTeacher() { return hasRole('teacher'); }
function isAdmin()   { return hasRole('admin') || request.auth.token.admin == true; }
```

## 3. Firestore Collection Hierarchy & Schemas

KidQuest Authoritative Collections follow **PascalCase** naming to match the existing production codebase (`Frontend/services/` and `Backend/functions/src/`).

```
Firestore Root
├── Users/{uid}                     (Parent, Kid, and Teacher Profiles)
├── Tasks/{taskId}                  (Chores, Homework & Daily Goals)
├── TaskSubmissions/{submissionId}  (Photo proof & verification audit trail)
├── Rewards/{rewardId}              (Reward Catalog defined by Parents)
├── RewardClaims/{claimId}          (Redemption requests & fulfillment status)
├── XpLedger/{entryId}              (Immutable audit log of XP transactions)
├── FamilyCodes/{code}              (6-character alphanumeric parent link codes)
├── Schools/{schoolId}              (School institutional profiles)
│   └── Classes/{classId}           (Classrooms, rosters & teacher assignments)
└── Notifications/{notifId}         (User notification items)
```

### 3.2 `Tasks/{taskId}` Collection

Chores, homework, ya positive habits jo parent ya teacher assign karta hai.

```typescript
type TaskCategory = 'homework' | 'chores' | 'reading' | 'exercise' | 'creative' | 'kindness' | 'other';

  finalXp?: number;             // Actual XP awarded after parent approval

  assignedToUid: string;        // Target child UID
  assignedToName: string;       // Cached display name

  proofNote?: string;           // Optional note submitted by child
  parentNote?: string;          // Feedback note provided by parent upon review
  dueDate: Timestamp;
  completedAt?: Timestamp | null;
  approvedAt?: Timestamp | null;
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

## 4. Security Rules Matrix (Least-Privilege)

| Collection | Create | Read | Update | Delete |
|---|---|---|---|---|
| `Users/{uid}` | Parent self / Admin | Self, Linked Parent, Class Teacher | Self (name/avatar only, NO role/xp change) | Self (or Parent for linked kid) |
| `Tasks/{taskId}` | Parent for linked kid; Teacher for student | Assigned Kid, Linked Parent, Teacher | Child (submit proof only); Parent (approve/reject); Teacher | Parent creator or Teacher |
| `TaskSubmissions` | Assigned Kid only | Assigned Kid, Linked Parent, Teacher | Parent or Teacher (review only) | False (Immutable audit) |
| `Rewards/{rewardId}` | Parent only | Linked Kids & Managing Parent | Managing Parent only | Managing Parent only |
| `RewardClaims` | Cloud Function / Kid | Claiming Kid & Managing Parent | Managing Parent (approve/reject) | False |
| `XpLedger` | **FALSE** (Cloud Functions only) | Kid owner & Managing Parent | **FALSE** | **FALSE** |
| `FamilyCodes` | Parent only | Signed-in users (to link family) | Managing Parent | Managing Parent |
| `Schools & Classes` | Admin / Teacher | Enrolled Students & Class Teacher | Class Teacher / Admin | Admin |
| `Notifications` | Signed-in / Cloud Function | Recipient only (`recipientId == auth.uid`) | Recipient (`isRead: true` only) | Recipient only |

## 5. Storage Security Rules Matrix

| Path Pattern | Read Access | Write Access | Delete Access | Restrictions |
|---|---|---|---|---|
| `profile-photos/{uid}/{fileName}` | Self, Linked Parent, Class Teacher | Self or Linked Parent | Self or Linked Parent | Max 5MB, `image/(jpeg\|png\|webp)` |
| `task-photos/{taskId}/{fileName}` | Assigned Kid, Linked Parent, Class Teacher | Assigned Kid (`assignedToUid == auth.uid`) | Assigned Kid or Linked Parent | Max 10MB, `image/(jpeg\|png\|webp)` |
| Default `/{allPaths=**}` | **FALSE** | **FALSE** | **FALSE** | Default deny |

## 6. Firebase App Check Architecture

To prevent API abuse, scraping, and unauthorized automated requests, Firebase App Check must be initialized:

1. **Android:** Play Integrity API (`PlayIntegrityProvider`).
2. **iOS:** Apple App Attest / DeviceCheck (`AppAttestProvider`).
3. **Web / Portal:** reCAPTCHA Enterprise (`ReCaptchaEnterpriseProvider`).
4. **Development / Emulators:** Debug Token Provider (`DebugAppCheckProvider`).
